# 我在 - 智能语音代说助手

> 随时随地，我一直都在。
>
> 给中老年出境旅行者使用的温暖陪伴型沟通工具。

## 产品定位

**我在** 不是一个传统翻译软件，而是一个“语音代说助手”。

它要解决的不是“把一句话翻译成另一种语言”这么简单，而是帮助不熟悉外语、不擅长操作手机的长辈，在国外可以更安心地开口、求助、问路、购物和办理事务。

核心体验是：

> 您用中文说，我替您说给对方听。

产品设计优先级：

1. 降低操作门槛
2. 减少步骤
3. 消除心理恐惧
4. 提升表达与翻译质量

## 当前能力

### 1. 替用户说给对方听

用户点击首页大圆按钮，说出中文需求，系统会完成：

- 实时语音识别
- 语义补全与表达整理
- 生成目标语言表达
- 大字展示给对方看
- 自动语音播放给对方听

结果页提供：

- 查看原句
- 再播放一次
- 重新说
- 对方说话，我帮您听

### 2. 听对方说话，帮用户理解

在结果页点击 **对方说话，我帮您听**，进入反向沟通模式。

系统会听对方说的外语，并整理成中文展示，同时支持中文语音播报。长内容会在结果卡片内部滚动，避免页面整体被撑开。

### 3. 快捷短语，一点即用

首页提供三个高频场景短语，点击即可直接代说，无需说话或打字：

- 洗手间在哪里
- 这个多少钱
- 怎么办理托运

### 4. 识别失败时不吓人

当麦克风、网络或浏览器语音服务不稳定时，页面不会显示空白或报错代码，而是进入友好的失败页：

- 明确提示“刚才没有听清”
- 提供大按钮“重新说”
- 提供打字兜底：“着急时也可以直接打字”
- 点击“替我说这句”继续完成沟通

### 5. 紧急求助与基础设置

底部固定栏包含：

- 紧急求助
- 当前语言
- 自动语音开关

子女可以提前帮长辈设置目标语言和自动播放状态。

## 设计原则

### 适老化与防老花

- 大字号、高对比、清晰边界
- 单核心操作入口
- 页面尽量一屏完成
- 关键状态持续反馈
- 按钮文案口语化，例如“开始说话”“重新说”“查看原句”

### 温馨陪伴感

产品语言避免强调“翻译”，更多使用：

- 替您说
- 帮您表达
- 帮您听懂
- 帮您整理成中文

这让用户感受到的是“有人在帮我沟通”，而不是“我要操作一个工具”。

### 视觉风格

当前页面采用移动端优先的小程序式界面：

- 暖米色背景
- 柔和复古色彩
- 大圆语音按钮
- 卡片式结果展示
- 桌面端居中手机沙盒预览
- 手机端全屏流布局

## 技术实现

### 前端结构

```text
我在/
  ├─ index.html      # 主页面
  ├─ css/style.css   # 视觉与响应式样式
  ├─ js/app.js       # 语音、代说、帮听懂、状态流转
  ├─ intro.html      # 介绍页
  └─ assets/         # 静态资源
```

### 核心技术

- Web Speech API：语音识别与语音合成
- CSS 响应式布局：移动端全屏、桌面端居中沙盒
- LocalStorage：目标语言、自动播放、API Key 等本地配置
- 翻译服务链路：优先专业 API，失败后本地高频场景兜底

## 翻译与语义服务配置

当前代码支持三层兜底：

1. 自定义后端代理接口
2. DeepL Free API
3. 本地常用场景表达

### 方式一：配置后端代理接口

推荐在生产环境使用后端代理，避免把 API Key 暴露在浏览器中。

前端会读取：

```javascript
window.WOZAI_TRANSLATE_ENDPOINT
```

或：

```javascript
localStorage.setItem('wozaiTranslateEndpoint', 'https://your-domain.com/api/translate');
```

请求体示例：

```json
{
  "text": "请问洗手间在哪里？谢谢。",
  "source": "zh-CN",
  "target": "en-US",
  "targetName": "英语"
}
```

返回体示例：

```json
{
  "translated": "Excuse me, where is the restroom? Thank you.",
  "optimized": "请问洗手间在哪里？谢谢。"
}
```

反向“帮我听懂”也可使用同一个代理接口，返回中文结果即可。

### 方式二：临时配置 DeepL

开发测试时可在浏览器控制台设置：

```javascript
localStorage.setItem('deeplAuthKey', 'your-deepl-free-key');
```

DeepL 不支持或网络失败时，会自动回落到本地兜底表达。

## 浏览器兼容

| 环境 | 支持情况 | 说明 |
| --- | --- | --- |
| Chrome / Edge | 较好 | Web Speech API 支持较完整 |
| iOS Safari | 可用 | 需要用户主动点击后启动识别 |
| 微信内置浏览器 | 不稳定 | 页面会引导用户使用系统浏览器打开 |
| 无网络或识别服务异常 | 可兜底 | 支持重新说和打字代说 |

> 注意：浏览器提示麦克风权限通过后，仍可能出现“识别服务不稳定”。这通常是浏览器云端听写服务不可达，不等同于麦克风权限失败。

## 子女预设建议

在父母出行前，建议提前完成：

1. 打开页面，允许麦克风权限。
2. 点击“当前语言”，选择目的地语言。
3. 确认“自动语音已开启”。
4. 演示一次“洗手间在哪里”快捷短语。
5. 演示一次“对方说话，我帮您听”。
6. 告诉父母：听不清时点“重新说”，着急时可以直接打字。

## 后续优化方向

- 接入更稳定的服务端语音识别，减少 Web Speech API 兼容问题。
- 接入专业翻译或大模型语义整理，提高口语、方言、不完整表达的理解质量。
- 增加更多旅行高频兜底场景，例如海关、酒店、药店、交通、支付。
- 针对不同国家语言补充更礼貌、更本地化的表达。
- 增加离线提示和网络状态提示，进一步降低用户焦虑。
